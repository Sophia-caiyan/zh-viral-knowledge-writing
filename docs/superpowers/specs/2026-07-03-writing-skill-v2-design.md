# 中文高共鸣公众号长文 Skill V2 设计

日期：2026-07-03

## 1. 目标

将现有 `zh-viral-knowledge-writing` 从“通用写作规则集合”升级为一套经过语料验证、带标题系统和质量评测的公众号长文 Skill。

首版只保证：

- 公众号长文，建议成稿长度 2000-3500 字。
- AI、心理学、教练、职场与个人成长等知识型选题。
- 从选题诊断、标题设计到正文成稿的一体化流程。
- 可公开安装和分享，不依赖作者本机的一千多篇原始 PDF。

成功不是“像某个作者”，而是稳定产出以下效果：

- 标题让目标读者感到“这件事和我有关”。
- 开头快速出现人物、场景、冲突或代价。
- 全文有一个明确、可辩护的判断。
- 情绪负责推动阅读，知识负责兑现价值。
- 正文完整交付标题承诺。
- 不编造经历、案例、研究或产品事实。

## 2. 非目标

V2 暂不负责：

- 小红书笔记、短视频口播、朋友圈、微博等短内容。
- 新闻摘要、学术报告、纯 SEO 文章或品牌通稿。
- 逐句复制任何在世作者的个人口吻、口癖或身份。
- 将原始文章全文公开到 GitHub。
- 训练或微调模型。
- 在缺乏真实材料时编造第一手经历来换取“活人感”。

## 3. 核心原则

### 3.1 用全量语料验证，用代表作深拆

一千多篇文章不直接进入每次生成的上下文。它们承担两种研究任务：

1. 全量统计：验证标题、篇幅、段落、问句、对话、读者指称等规律是否普遍。
2. 分层深拆：研究不同文章原型如何开头、立冲突、推进情绪、给出判断和收尾。

公开 Skill 只携带由语料提炼出的规则、原型、改写示例、统计结论和检查标准。

### 3.2 标题是正文合同

标题不是正文写完后的包装。标题中的读者、冲突、判断和收益必须在正文中逐项兑现。

任何候选标题都要回答：

- 写给谁？
- 刺中什么情绪或代价？
- 对抗什么误解、规则或处境？
- 给出什么判断或阅读收益？
- 现有材料能否证明？

无法被正文证明的标题不得入选。

### 3.3 人格稳定高于口癖稳定

Skill 使用一个可迁移的写作者人格：

> 站在具体的人这一边，把普通人说不清的焦虑、委屈、欲望和不甘说清楚，再给出一个有用、负责的判断。

该人格有四条价值底色：

- 先理解处境，再下判断。
- 敢说结论，但承认证据边界。
- 情绪可以强，不能通过羞辱弱者制造爽感。
- 知识必须落回生活场景和可执行动作。

### 3.4 质量来自闭环，不来自规则数量

每次生成都经过：

> 诊断选题 → 选择原型 → 设计标题 → 建立标题合同 → 写正文 → 四层检查 → 自动修订

Skill 的升级也经过：

> 固定测试集跑 V1 基线 → 编写 V2 → 同题盲测 → 找失败模式 → 修正规则 → 再测

## 4. 公开层与私人层

### 4.1 公开层

公开 GitHub 仓库包含：

- 核心 Skill。
- 由语料提炼的统计和方法。
- 经过改写或合成的功能示例。
- 硬规则检查脚本。
- 固定评测题和评分标准。
- 安装、使用和评测说明。

公开层必须能独立工作。生成文章时不得假设用户拥有原始语料。

### 4.2 私人增强层

作者本机可以保留：

- 原始 PDF。
- 阅读数据表。
- 全文索引。
- 文章级特征卡。
- 原文检索脚本输出。

私人层只用于继续研究和校准，不提交 Git。检索结果只应抽取结构特征，不应在输出中大段复现原文。

## 5. 语料研究设计

### 5.1 已有语料基础

- 1111 条文章元数据。
- 911 条记录匹配到本地 PDF。
- 719 篇正文至少包含 1500 个可提取中文字符。
- 已有 116 篇按类别、年份和点赞层级分层的研究样本。

### 5.2 全量统计

对 1111 个标题和 719 篇可读正文统计：

- 标题长度、标点、代词、数字、问句和情绪词。
- 标题钩子类型及其组合。
- 全文字数、段落长度和单句成段比例。
- 问句、反问、对话、读者直呼和价值判断出现频率。
- 开头 300 字出现人物、冲突、时间、地点和核心判断的比例。
- 结尾 300 字采用判断、许可、号召、边界或回环的比例。

统计只用于发现候选规律。不得把相关性表述成确定的传播因果。

### 5.3 116 篇深度特征卡

每篇文章使用同一结构记录：

- 文章类别与次级类别。
- 默认读者身份。
- 主情绪与次情绪。
- 标题钩子。
- 开头方式。
- 冲突双方。
- 作者姿态：撑腰、审判、拆穿、安慰、骂醒或行动指导。
- 反常识判断。
- 故事弧和信息揭示顺序。
- 论据类型。
- 情绪推进节点。
- 金句机制。
- 结尾方式。
- 可迁移动作。
- 不应迁移的作者专属口癖或时代语境。

特征卡使用结构化数据保存，方便聚合和复查。

### 5.4 留出验证集

从 719 篇正文中另选 24 篇作为留出集，不参与规则撰写。

规则完成后检查：

- 文章原型能否覆盖留出文章。
- 标题分类是否能解释其主要钩子。
- 开头、正文、结尾规则是否遗漏高频机制。
- 是否把少数极端文章误当作普遍规律。

## 6. 标题系统

### 6.1 标题钩子分类

V2 首版支持八类钩子：

1. 情绪代言：替读者说出委屈、不甘、羞耻或焦虑。
2. 强判断：对一个行为、规则或关系直接下结论。
3. 反常识：推翻读者原有解释。
4. 身份镜像：让某类人立即认出自己。
5. 具体代价：钱、时间、尊严、关系、机会或判断力。
6. 关系冲突：两种角色、利益或价值发生碰撞。
7. 故事悬念：异常人物、事件、结果或反差。
8. 实用收益：明确承诺方法、清单或解决方案。

每个标题至少包含两类钩子，通常不超过四类。

### 6.2 标题生成流程

1. 提取读者、处境、隐秘情绪、对立面、核心判断和实际收益。
2. 生成不少于 12 个候选标题，覆盖至少四种钩子组合。
3. 删除材料无法兑现、过度羞辱、事实不准确或过于抽象的标题。
4. 对剩余标题评分并选出前三名。
5. 为第一名建立标题合同后再写正文。

### 6.3 标题评分

总分 100：

- 读者相关性：20。
- 冲突与张力：20。
- 观点新鲜度：15。
- 具体程度：15。
- 正文可兑现度：20。
- 转发表态价值：10。

硬性淘汰项：

- 标题包含正文无法证明的事实。
- 标题承诺的方法正文没有提供。
- 标题针对脆弱群体进行羞辱。
- 只剩情绪，没有可辩护的判断。
- 依赖空泛词，如“认知升级”“底层逻辑”“时代红利”。

### 6.4 标题合同

成稿前生成内部标题合同：

| 标题要素 | 正文交付位置 |
| --- | --- |
| 目标读者 | 开头现场或第二段 |
| 核心冲突 | 第一部分 |
| 反常识判断 | 第一屏或前 20% |
| 事实或案例 | 中段论证 |
| 方法或答案 | 后半部分 |
| 情绪出口 | 结尾 |

该合同默认不展示给用户，但必须用于写作和质检。

## 7. 公众号长文原型

V2 首版采用六种原型：

### 7.1 情绪代言型

用于委屈、羞耻、焦虑、被忽视或被规训的处境。

结构：

> 具体受伤现场 → 说出隐秘情绪 → 揭示坏逻辑 → 强判断 → 证据与反例 → 新边界 → 情绪出口

### 7.2 关系真相型

用于伴侣、家庭、同事、管理者、教练与来访者等关系议题。

结构：

> 关系摩擦 → 表面问题 → 隐藏交易或权力结构 → 承认对方处境 → 新判断 → 可执行边界

### 7.3 职场利益型

用于 AI、效率、职业、金钱、谈判和组织规则。

结构：

> 吃亏现场 → 常见安慰为何无效 → 利益或成本机制 → 反常识规则 → 行动方案 → 身份升级

### 7.4 成长反鸡汤型

用于心理学、教练和个人成长。

结构：

> 一个努力却无效的人 → 拆穿错误努力 → 解释心理机制 → 给出有限度的新选择 → 小行动 → 许可式结尾

### 7.5 故事人物型

只在用户提供真实人物、公开案例或可核实材料时使用。

结构：

> 异常结果 → 延迟解释 → 人物选择 → 代价与转折 → 意义反转 → 普遍判断

若没有可靠故事素材，切换到其他原型，不得编造人物经历。

### 7.6 知识方法型

用于提示词、工作流、沟通方法和教练工具。

结构：

> 失败现场 → 常见方法为何失效 → 新框架 → 3-5 个动作 → 每个动作的生活化例子 → 学习成本 → 行动结尾

## 8. 写作流程

### 8.1 输入诊断

内部整理：

- 主题。
- 目标读者。
- 发布目的。
- 用户已有观点。
- 可用事实与案例。
- 读者隐秘情绪。
- 对立面。
- 可辩护的反转。
- 适用原型。
- 风险领域。

### 8.2 素材门槛

把输入分为三档：

- A 档：有真实故事、事实和作者观点，可写完整成稿。
- B 档：有观点和部分材料，允许写成稿，但标记待补证据位置。
- C 档：只有一个主题，先产出角度、标题和结构；不得假装已有真实经历。

若用户明确要求一次成稿，C 档可以使用“典型场景”解释问题，但必须明确其为说明性场景，不得写成亲历故事。

### 8.3 正文节奏

- 前 20% 完成现场、冲突和核心判断。
- 每个抽象观点后紧跟场景、例子或具体后果。
- 情绪段与知识段交替，避免连续煽情。
- 每一部分都推进新信息，不重复同一句判断。
- 短段落用于降低阅读负担，不能把每句话机械拆段。
- 结尾提供语言、边界或行动，不复述全文目录。

## 9. 四层质量系统

### L1：硬规则

脚本扫描：

- 空泛开头和 AI 套话。
- “首先、其次、最后、综上所述”等报告式连接词。
- 连续超长段落。
- 过量小标题、列表和加粗。
- 未清理的占位符。
- 未标注的高风险确定性表达。
- 用户指定的禁用词。

脚本只负责可确定匹配的词语、格式和长度问题。事实真伪、心理学越界、标题是否真正被论证等语义问题必须由 L2-L4 检查，不能用正则表达式假装解决。

脚本接口固定为：

```text
python scripts/lint_draft.py --title "文章标题" --input article.md --json
```

通过时退出码为 0；发现问题时退出码为 1，并输出规则编号、严重级别、命中位置和修改建议。脚本不联网、不修改原稿。

### L2：标题合同

逐项检查标题中的人物、冲突、判断、方法和结果是否在正文出现并得到支持。

任何关键承诺未兑现，优先修改正文；如果材料不足，则降低标题承诺。

### L3：内容质量

评分 1-5：

- 读者代入。
- 开头牵引。
- 冲突清晰。
- 判断力度。
- 推理与证据。
- 实用价值。
- 节奏推进。
- 结尾传播力。

任何一项低于 3，自动修订一次。

### L4：真人感与伦理

终审问题：

- 它是在替具体的人说话，还是在输出抽象概念？
- 它有明确判断，还是只有漂亮句子？
- 情绪来自真实处境，还是靠夸张和羞辱？
- 有没有编造亲历、案例、研究或当前产品事实？
- 读者读完得到的是行动和语言，还是短暂愤怒？

最多自动修订两轮。仍未通过时，应明确指出缺少什么素材，不继续堆砌文字。

## 10. 功能示例库

示例库不保存整篇原文，而按功能提供短对照：

- 抽象标题 → 有读者、有冲突、可兑现的标题。
- 教科书开头 → 具体现场开头。
- 只讲概念 → 场景加机制。
- 只煽情 → 情绪加证据和行动。
- 空洞金句 → 从前文自然长出的判断。
- 编造亲历 → 诚实的说明性场景。
- 标题党 → 降低承诺或补足正文。
- AI 初稿 → V2 修改稿，并标注修改动作。

示例优先使用 AI、心理学和教练主题的合成文本，避免复制原作者独特表达。

## 11. Skill 与仓库结构

公开仓库调整为：

```text
README.md
skill/
  zh-viral-knowledge-writing/
    SKILL.md
    agents/
      openai.yaml
    references/
      title-system.md
      article-archetypes.md
      style-examples.md
      domain-adaptation.md
      quality-system.md
    scripts/
      lint_draft.py
evals/
  cases.json
  rubric.md
  README.md
research/
  corpus-method.md
  aggregate-findings.md
```

设计理由：

- 仓库根目录服务 GitHub 读者和贡献者。
- `skill/zh-viral-knowledge-writing/` 是可安装的纯 Skill，不混入研究和项目文档。
- `evals/` 让质量标准可以复现。
- `research/` 说明结论如何得出，但不包含原始文章。

渐进加载规则：

- 所有完整写作请求都加载 `title-system.md` 和 `quality-system.md`。
- 根据选中的文章原型加载 `article-archetypes.md`。
- AI、心理学或教练主题加载 `domain-adaptation.md` 对应章节。
- 只有需要成稿或诊断改写时才加载 `style-examples.md`。

现有文件迁移：

- `references/mimeng-patterns.md` 拆入标题、文章原型和研究结论。
- `references/topic-adaptation.md` 合并到领域适配和核心输入诊断。
- `references/output-recipes.md` 中仍有效的输出约定合并到 `SKILL.md` 与质量系统。
- 迁移完成后删除旧文件，避免两套规则冲突。

本机安装目录继续是：

```text
~/.codex/skills/zh-viral-knowledge-writing/
```

只同步 `skill/zh-viral-knowledge-writing/` 中的内容。

## 12. 评测设计

### 12.1 固定测试集

建立 24 个公开测试题：

- AI：8 个。
- 心理学：8 个。
- 教练：8 个。

每个领域覆盖：

- 只有选题。
- 选题加零散观点。
- 有完整但平淡的初稿。
- 有事实材料，需要重写。

测试题不包含预期文章，避免把 Skill 训练成固定答案。

### 12.2 RED：V1 基线

修改 Skill 前，用当前版本生成全部 24 个测试题，记录：

- 标题候选。
- 推荐标题。
- 正文。
- 自检结果。
- 硬规则命中。
- 评分和主要失败原因。

预期基线失败包括：

- 标题公式化或与正文脱节。
- 开头只换一种说法重复选题。
- 情绪和知识像两篇文章拼在一起。
- 段落都很短但没有信息推进。
- 自检只描述优点，没有触发重写。

### 12.3 GREEN：V2 同题测试

V2 使用完全相同的输入生成文章。评审者看不到版本信息，按统一量表打分。

评测协议：

- V1 与 V2 使用同一模型、同一推理强度和同一工具权限。
- 每个版本每道题生成一次；出现工具错误时允许原条件重跑，不得因文章质量不佳而重抽。
- 输出随机标记为 A/B，评分阶段隐藏版本。
- 硬规则和标题合同记录客观结果；其余维度由人工按 `evals/rubric.md` 评分。
- 公开提交每题分数、失败标签和聚合结果；完整长文运行产物保留在本地，不提交仓库。
- 模型随机性意味着分数不是跨模型的永久保证，因此发布结论必须注明测试模型、日期和运行条件。

权重：

- 标题质量与兑现：20%。
- 读者代入：15%。
- 开头牵引：15%。
- 结构与节奏：15%。
- 观点、证据与实用性：20%。
- 真人感：10%。
- 结尾传播力：5%。

### 12.4 发布门槛

V2 发布需同时满足：

- 总分平均不低于 80/100。
- 任一核心维度不得低于 3/5。
- 至少 70% 的测试题比 V1 高 10 分或以上。
- 标题关键承诺未兑现为 0。
- 编造事实、经历或来源为 0。
- `lint_draft.py` 的单元测试与 24 篇 V2 输出检查全部通过。
- Skill 基础结构验证通过。

若不能满足，不以“风格主观”为由发布，必须记录失败类型并继续迭代。

## 13. 错误处理

- 缺真实案例：切换非故事原型，或标记需要补充的素材。
- 缺当前事实：请求来源或联网核实，不靠记忆补全。
- 标题无法兑现：降低标题承诺，不强行扩写。
- 心理学内容越界：使用体验性语言，不给诊断。
- 情绪过强：增加对立面理解、证据和行动方案。
- 文章低于质量线：最多修订两轮，之后说明缺口。

## 14. 验收标准

实现完成后，用户应能：

1. 安装公开 Skill，不需要本地原始语料。
2. 给出一个 AI、心理学或教练选题，获得标题和公众号长文。
3. 看见推荐标题为什么成立，以及正文如何兑现。
4. 用同一评测标准复测输出。
5. 在 GitHub 中理解研究依据、安装方式和版权边界。

V2 的最终价值不是让每篇文章长得一样，而是让不同选题都经过同一套可靠判断：

> 找到具体的人，抓住真实的痛，给出值得传播的判断，并用正文把标题承诺完整交付。
