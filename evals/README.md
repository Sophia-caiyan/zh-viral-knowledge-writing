# Evaluations

This folder contains public prompts and scoring rules for checking whether the skill improves real writing quality.

## How To Run

1. Use the same model, reasoning setting, and tool access for every compared version.
2. Run each prompt in `cases.json` once per version.
3. Save full outputs locally outside the repository, for example under `eval-runs/`.
4. Score each output with `rubric.md`.
5. Commit only aggregate scores and failure tags, not long generated drafts.

## Why No Golden Answers

There is no single correct article for a writing prompt. The fixed cases test whether the skill consistently produces stronger titles, openings, structures, and ethical boundaries. The rubric is the contract.

## What To Compare

For each case, record:

- Skill version or commit.
- Model and date.
- Recommended title and subtitle.
- Score out of 100.
- Core 1-5 ratings.
- Failure tags.
- Whether the title contract was fully delivered.
- Whether any fact, case, source, or first-person experience was fabricated.

## Local Artifacts

Full generated drafts can be long and model-specific. Keep them local unless there is a specific reason to publish a short excerpt that was generated by the model, not copied from any source corpus.
